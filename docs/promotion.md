## 面向开发者：掘金/CSDN/知乎/微信公众号

标题候选：

- 我用 AI 做了一个本地优先的微信记账小程序，并开源了
- 从 0 到 GitHub：一个微信记账小程序 MVP 的开发记录
- 不接后端也能跑：微信小程序本地记账 MVP 实战

正文草稿：

最近我做了一个本地优先的微信记账小程序，定位很简单：先让自己每天能顺手记一笔，再慢慢补同步、导入、AI 分类这些高级能力。

项目目前已经开源，仓库地址：

https://github.com/Jennifer-ra/accounting

第一版没有接后端，也没有引入 npm。数据直接保存在微信小程序本地缓存里，核心数据包括账单、分类、账户和本月预算。这样做的好处是启动成本很低，隐私边界也清楚：MVP 阶段先不上传任何账单数据。

目前已经实现的功能包括：首页快速记支出/收入、账单列表、账单编辑、月份筛选、分类统计、自定义分类、自定义账户、本月预算、JSON 导入导出，以及一个简单的 CSV 账单导入器。

我把项目放成了 monorepo 结构：

```text
accounting/
  apps/
    wx-accounting-mvp/
```

后面会继续加：

```text
services/go-api/
packages/importers/
docs/
```

也就是说，这不只是一个小程序 demo，后续会逐步扩展成一个完整的个人记账产品实验：前端小程序、Go 后端、账单导入器、AI 自动分类都会放在同一个主题仓库里。

为什么第一版选择本地优先？

因为记账产品最难的不是技术炫技，而是用户愿不愿意每天打开。相比一开始就做登录、云同步、复杂权限，我更想先验证三个问题：

1. 记一笔是否足够快？
2. 本月花了多少钱是否一眼能看懂？
3. 历史账单是否能方便迁移？

下一步我计划优先做微信/支付宝账单 CSV 的稳定解析器，然后补周期记账、预算提醒和 Go 后端同步。如果你也对微信小程序、记账产品、本地优先架构或 AI 辅助开发感兴趣，欢迎 star、提 issue 或一起优化。

- 账单先存在自己手机里：一个本地优先记账小程序

正文草稿：

我最近做了一个很轻量的微信记账小程序，名字暂时叫“轻记账”。

它的想法很简单：打开就能记一笔，不需要注册账号，不需要先登录，也不会在第一版把你的账单上传到服务器。数据先保存在当前微信环境里，你也可以手动导出备份。

现在可以做这些事：

- 快速记录支出和收入
- 查看本月收入、支出和结余
- 设置本月预算，看还剩多少钱
- 按月份查看账单
- 看餐饮、交通、购物等分类统计
- 自己添加分类和账户
- 导出或导入账单数据

我自己做它的原因很朴素：很多记账工具功能很完整，但打开后步骤有点多。我想先做一个足够顺手的小工具，让“记一笔”这件事尽量轻。

后面准备继续补：微信/支付宝账单导入、周期记账、预算提醒、多端同步和自动分类。

如果你也经常想记账但坚持不下来，可以先关注这个项目。等体验版整理好后，我会放出小程序体验入口。
